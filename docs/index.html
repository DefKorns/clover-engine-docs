Clover engine reference

The console UI stack of the SNES Classic, NES Classic, Famicom Mini and the Shonen Jump Famicom Mini: what runs, which files it reads, which Lua it exposes, and where the three engine families differ.

Status: working reference, kept on disk. Method and confidence are in section 10; open questions in section 11. Nothing here was run on a console.

1. Architecture

Three layers run on the console (ARM 32-bit Linux):

clover-mcp               supervisor: display, games, lifecycle, error screens
   |  starts / waits on
   v
ReedPlayer-Clover        the engine: scene graph, components, resources, Lua VM
   |  loads
   v
UI package (resources/)  scenes, sprites, sounds, strings, Lua scripts: the part a theme replaces
  • Supervisor. Reads clover-mcp.desktop, scans the games and writes the title list for the menu, starts the menu or a game as a child process, and shows splash and error screens (section 4).
  • Engine. ReedPlayer-Clover, about 1.2 MB. A node tree with components (textures, labels, sounds, animations), a resource manager driven by dependencies.json, and an embedded LuaJIT 2.0.4 that runs the UI scripts (sections 5 to 7). It runs the menu UI and the games' own front-ends alike.
  • UI package. The files under /usr/share/ui/<name> (for example snes-eur, hvc): init.json, the scenes, dependencies.json, sprites, sounds, strings and the compiled Lua. A theme replaces or overlays part of it.

The supervisor and the engine communicate through a command file and a state file, plus eventfds for the menu to game transitions (Settings.CommandFile, Settings.StateFile).

3. Boot and process lifecycle

  1. The supervisor starts (executeStartup): reads settings, opens the framebuffer and display device, shows the startup splash, scans the games folder and writes menu.titles.lua.
  2. It starts the menu: the engine runs the UI package's init.json default scene and its Lua. The UI's sys_boot script builds the boot screen, loads fonts and textures, and hands over to the Main scene.
  3. In the menu, the user picks a game. The menu writes a command; the supervisor stops the menu, starts the game and waits. On the way back it starts the menu again.
  4. In the SNES and Shonen supervisors the two transitions (menu to game, game to menu) wait up to 20 s on an eventfd.
  5. Failures draw a full-screen splash and wait (section 4.5).

UI boot sequence (Lua)

  • sys_boot.lua: start sets sys_boot.instance, plays bootSound if linked, and shows the error dialogs for TITLE_RETURN_CODE (previous game crashed, suspend point unusable, rewind corrupted...); it also provides loadFont.
  • main.lua: loads the main music (resMainBGM); while the boot music (Main.bootBGM) plays it waits, then starts mainBGM and disables bootBGM (section 8.1).

4.3 The game scan

In executeStartup: opendir(GamesFolder); for each sub-directory not starting with ., parse <dir>/<dir>.desktop as INI, check for pixelart/<name>.png, autoplay/<name>.inputs and superplay/<name>.inputs, replace - by _ in the id, and emit one entry of titles_list = { ... } into MenuLuaFile (/var/cache/clover/menu.titles.lua). The scan has no time limit of its own.

4.4 Timeouts

SNES and Shonen: the menu to game and game to menu transitions wait on an eventfd with select() for 20 000 000 µs (20 s) (FUN_0001d710(fd, 20000000) in SNES 0x17860, at two places; FUN_0001dce0 in Shonen 0x17d40). Expiry records MENU TO GAME TRANSITION TIMEOUT or GAME TO MENU TRANSITION TIMEOUT. The NES supervisor has no such wait (its 2 000 000 000 ns values are 2 s shutdown timeouts).

4.5 Error screens

Every error screen is a full-screen LZ4 image, listed per locale in [X-CLOVER Errors]: a raw 1280x720 BGRA framebuffer of 3 686 400 bytes after decompression.

Failure messages (stderr, FATAL ERROR: ...): CLOVER GAME CRASHED (also DURING RESET, DURING SHUTDOWN), CLOVER MENU CRASHED (also DURING SHUTDOWN), CLOVER TEST MENU CRASHED, GAME TO MENU TRANSITION TIMEOUT, MENU TO GAME TRANSITION TIMEOUT, INVALID SETTINGS, UNABLE TO INITIALIZE SYSTEM, UNABLE TO RESUME CLOVER GAME, UNABLE TO START CLOVER GAME, UNABLE TO START CLOVER MENU, UNABLE TO START CLOVER SUPER PLAY, UNABLE TO START CLOVER TEST MENU, UNKNOWN CLOVER MENU COMMAND, WILD UNKNOWN ERROR APPEARED. The other error codes belong to the Lua UI (sys_error_* in strings/*/strings.lng): C2 menu settings reset, C4 suspend point could not be stored, C6 suspend point unusable, C7 game crash, C9 rewind data corrupted.   • resources: { id, type, path?, content?, contentType?, groupId, dependencies: [{ id, refCount }] }. 5.3 Scene node

{ id, components: [{ id, type }], children: [...] } plus the node keys name, transform, enabled, zIndex, category, visible, color, and for scripts scriptType and properties. A script property that links another object is { linkType, linkId } (or scriptTypeVariable).

5.4 Textures and sprite sheets (the .json next to a .png)

  • Texture: type, format, width, height, mipmapCount, keepOnCpuAfterUpload, under a platform key (Linux).
  • Sprite sheet: texture { id, width, height }, sprites { <name>: { textureFrame, sourceSize, sourceOffset, pivot } }.
  • Sprite resource: textureId, textureFrame, pivot, sourceSize, sourceOffset.

5.5 Scene animation tracks

worldNodePath, componentType, propertyId, scriptPropertyName, scriptPropertySetter, keyCurves: [{ time, value, interp }]. There is one loader per value type (eleven in SNES and Shonen). scriptPropertySetter exists in the SNES and Shonen engines and not in the NES one: only they can animate a script property.

5.6 Strings (strings.lng)

strings, modifiers, groupName, params, exploded_strings, type, text, value, format.

7. The Lua layer

7.1 Bytecode

The scripts are LuaJIT 2.0 bytecode version 1, stripped (1b 4c 4a 01 02). The engine reports LuaJIT 2.0.4.

Compiler Reproduces the console's colors_eur.lua
luajit.exe 2.0.2 (Lua Compiler tool) yes, byte for byte (-b and -bs)
LuaJIT v2.0 at 592f9e3f5... or 2410b57fd..., -bs, Linux x64 no (1454 bytes against 1051); same output as each other

One file was tested. Whether the larger bytecode loads on a console was not tested.

7.3 Globals

REED_FINAL, REED_DEBUG, HOST_PLATFORM_IS_LINUX, and the PLATFORM_IS_* family (3DS, Wii U, Windows, Linux, Android, OSX, iOS) are set by the engine before the scripts run. TITLE_RETURN_CODE is passed by the supervisor (its strings include --title-code and TITLE_RETURN_CODE=).

8. Subsystems

8.1 Boot music (bgm_boot)

  • defaultscene.scn has a SoundComponent on Main, linked as Main.bootBGM: /sounds/hvc/bgm_boot.wav, autoPlay: false, volume: 1. It is identical in the HVC, NES, SNES and Shonen Bases.
  • Main.update waits for the main music to load; when not bootBGM:isPlaying() (or the sample position went back) it calls mainBGM:play() and bootBGM:disable().
  • sys_boot.lua plays bootSound only if linked; the link is empty in sys_boot.scn in both Bases checked.
  • The Shonen firmware calls bootBGM:disable() at the start of Main.start.
  • Engine behaviour on a component with no native sound object (SNES): isPlaying returns false and getSamplePosition returns 0.0, neither raises an error. A scene with bootBGM disabled therefore gives the same result as the Shonen disable() call, as far as the code shows (a theme then needs no dummy WAV).

8.2 Palettes (colors_*.lua)

Compiled Lua tables colors_<region> = { <name> = { r, g, b, a }, ... } (eur, usa, jpn). Scripts and labels refer to a colour by name (colorName). A change applies to every region's file.

8.3 Animations

Scene animations drive node properties (position, scale, texture, visibility) with key curves. In the SNES and Shonen engines a track may call a script property setter; the NES engine has no such track.

10. Method and confidence

  • Binaries. /usr/bin/ReedPlayer-Clover and /usr/bin/clover-mcp from the stock .hsqs images.
  • Decompilation. REA 6.8.0 with Ghidra 12.1.4 (Docker rea-agent-ghidra, offline). Function names are mostly FUN_xxxx, except the NES supervisor (unstripped). Disassembly with Capstone where Ghidra did not define a function (the Lua binding lambdas).
  • Lua. luajit-decompiler-v2 on the UI scripts; they are stripped, so locals are slotN.
  • Matching across families. Key sets of the deserializers and the names of Lua methods were compared as strings; a method name present in a binary does not prove it is bound to the same class.
  • Confidence. Confirmed: sections 4.1 to 4.4 (NES names, SNES by message), 5.1, 5.2, 5.5, 6 (SNES), 8.1 engine behaviour. Inferred or partial: the splash choice in the SNES inlined states, the Shonen id handling, components without keys.

The supervisor (clover-mcp)

/usr/bin/clover-mcp starts first. It owns the screen and the process lifecycle: it scans the games, starts the menu (ReedPlayer-Clover running the UI), starts the games, shows the splash and error screens, and handles shutdown.

Sources: SNES EUR 2.0.14 (stripped, 650 functions), NES 1.0.7 (unstripped, 641 functions, 79 named nerd::clover::*) and Shonen 3.0.1 (stripped). The NES build gives the names; the SNES and Shonen builds were matched to it by their messages.

The game scan

FUN_0001e290 (SNES) runs in the startup state:

  1. opendir(GamesFolder); for each sub-directory not starting with ..
  2. Parse <dir>/<dir>.desktop as INI.
  3. Check for pixelart/<name>.png, autoplay/<name>.inputs and superplay/<name>.inputs.
  4. Replace - by _ in the id, and emit one entry of titles_list = { ... } into MenuLuaFile.

It has no timeout of its own. The menu process then loads that Lua file.

Splash images

Every error screen is a full-screen LZ4 image (a raw 1280x720 BGRA framebuffer, 3 686 400 bytes) listed per locale in [X-CLOVER Errors]:

Key Screen (SNES EUR)
Errors.StartupFailed C1
Errors.Unknown C8

Which failure shows which image (confirmed in the NES build: the code copies Settings.Unknown or Settings.StartupFailed into the splash path before executeStartupFailure / executeGeneralFailure draw it):

  • Errors.StartupFailed (C1): only executeStartup, i.e. "UNABLE TO INITIALIZE SYSTEM".
  • Errors.Unknown (C8): executeMenuRunning, executeMenuShutdown, executeMenuCommand, executeGameReset, executeGameShutdown, executeTestMenuRunning.

In the SNES build the start-up handlers (FUN_0001e290, FUN_0001d948 start menu) read the StartupFailed field (+0xe0) and start game / resume game (FUN_0001ae98, FUN_0001b570) read the Unknown field (+0xdc). The splash source of the inlined running and shutdown states in FUN_00017860 was not resolved; by the NES layout it is Errors.Unknown.

Failure messages

All recorded to stderr as FATAL ERROR: <text>: CLOVER GAME CRASHED (also DURING RESET, DURING SHUTDOWN), CLOVER MENU CRASHED (also DURING SHUTDOWN), CLOVER TEST MENU CRASHED, GAME TO MENU TRANSITION TIMEOUT, MENU TO GAME TRANSITION TIMEOUT, INVALID SETTINGS, UNABLE TO INITIALIZE SYSTEM, UNABLE TO RESUME CLOVER GAME, UNABLE TO START CLOVER GAME, UNABLE TO START CLOVER MENU, UNABLE TO START CLOVER SUPER PLAY, UNABLE TO START CLOVER TEST MENU, UNKNOWN CLOVER MENU COMMAND, WILD UNKNOWN ERROR APPEARED.

The NES supervisor lacks CLOVER GAME CRASHED, GAME TO MENU TRANSITION TIMEOUT and MENU TO GAME TRANSITION TIMEOUT.

Transition timeouts

In the SNES and Shonen supervisors the menu to game and game to menu transitions wait on an eventfd with select() for 20 000 000 microseconds (20 s) (FUN_0001d710(fd, 20000000) in SNES 0x17860; FUN_0001dce0 in Shonen 0x17d40). A timeout records the matching TRANSITION TIMEOUT message. The NES supervisor has no such wait; its 2 000 000 000 ns values are 2 s shutdown timeouts.

Each track: worldNodePath, componentType, propertyId, scriptPropertyName, scriptPropertySetter, keyCurves: [{ time, value, interp }].

  • Eleven track loaders exist in the SNES and Shonen engines, one per value type.
  • scriptPropertySetter exists in the SNES and Shonen engines and not in the NES one: only they can drive a script property from an animation.

Strings (strings.lng)

strings, modifiers, groupName, params, exploded_strings, type, text, value, format.

Components

See scene-components.md for the keys per component. The Camera deserializer reads viewportRect, order, clearScreen, clearColor, categoryMask, targetScreen, renderTarget; the Clickable one reads layer, center, clickCallbackComponent, shape and, per shape, width, height or radius.

Differences between families

  • The NES deserializers read enabled, properties and scriptType inside each component; the SNES and Shonen read them once in a base.
  • The NES node has no visible and no color key; the NES visual component has no visible key.
  • Shonen: identical key sets to the SNES for every component.
  • Not confirmed: whether the Shonen loaders of nodes, components, sprite sheets and manifest entries read id (the extraction found it in the SNES one only; it may be an extraction miss).

Scene components (.scn)

Source: the component deserializers of ReedPlayer-Clover (SNES EUR 2.0.14, decompiled with REA/Ghidra). Each one reads JSON keys into fields of the component. Types come from the helper each call uses (bool, float, int, resource id). The key names were read from the strings in the data section.

The same 15 component types exist in the SNES, NES and Shonen engines; see family-differences.md.

Notes

  • colorName on a label is not read by the engine: it is a property the Lua scripts look up in the palette (colors_*.lua).
  • The engine does not mention needs_overlay as a string. It is not part of the engine or of the firmware: it is a marker file read by the theme selector (an hmod), which uses it to know that a theme must be applied with an overlay filesystem instead of a bind mount of its resources.
  • A SoundComponent that is disabled has no native sound object: isPlaying returns false instead of raising an error (see boot-music.md).

Lua API reference

Every class and method the engine exposes to Lua, with its signature, which engine families bind it, and the address of its binding in each build. Interactive version: index.html, page API explorer.

How to read this

  • Class:method(...) is an instance method (called with a colon); Class.method(...) is a static function of a global table (Application, FileUtils, Input, Localization, CRC64).
  • Parameter and return types come from the engine code: the helper each binding calls to read an argument or push a result (number, integer, boolean, string, or a resource class). any means the argument is read by a helper that was not classified. Parameter names are not in the binary: single-argument setters use the name after set, the rest are argN.
  • Families: S = SNES (EUR, USA, SHVC; identical API), N = NES and HVC (identical API), J = Shonen. The NES signatures list only the number of arguments: its binding code was not classified.
  • The summaries are derived from the method names. Lines under Note were verified in the code.

Boot music (bgm_boot)

Evidence: main.lua and sys_boot.lua of the SNES EUR and Shonen Bases (decompiled with luajit-decompiler), and ReedPlayer-Clover SNES EUR 2.0.14 (decompiled with REA/Ghidra).

How it plays

  • defaultscene.scn has a SoundComponent on the Main node, linked as Main.bootBGM, with the resource /sounds/hvc/bgm_boot.wav, autoPlay: false, volume: 1. The same component exists in the HVC, NES, SNES and Shonen Bases.
  • Main.update (main.lua) waits for the main music (resMainBGM) to load, then when not bootBGM:isPlaying() (or the sample position went back) it calls mainBGM:play() and bootBGM:disable().
  • sys_boot.lua plays bootSound only if that link is set. It is empty in sys_boot.scn in both Bases, so the boot screen itself plays nothing.

How the Shonen firmware silences it

Its Main.start calls bootBGM:disable() before anything else, then runs its own rotation of five tracks. The other Bases keep the sound and disable it only once the main music starts.

Engine behaviour that matters

  • SoundComponent:isPlaying (SNES FUN_000a75e4): if the component has no native sound object it returns false, with no error.

  • Component API: enable, disable, setEnabled, isEnabled.

  • SoundComponent:getSamplePosition (SNES 0xa7340, read from the disassembly): when the component has no native sound object it returns the constant 0.0, with no error. It is a Lua binding lambda that Ghidra did not define as a function.

Silencing without a dummy WAV

With the component disabled, Main.update behaves like this: the first getSamplePosition returns 0.0, so bgmSamplePosition is stored as 0.0; isPlaying returns false; the condition not bootBGM:isPlaying() is true and mainBGM:play() runs at once. Nothing in these paths raises an error. So a scene whose bootBGM component is disabled gives the same result as the Shonen firmware's bootBGM:disable(), as far as the code shows.

Not verified

  • That a component loaded with enabled: false in the scene has no native sound object (that is when the engine creates it was not read), and that nothing re-enables it.
  • Nothing was run on a console.

Error C8

Evidence: stock firmwares, supervisor clover-mcp (SNES EUR 2.0.14, NES 1.0.7 unstripped, Shonen 3.0.1), decompiled with REA/Ghidra, plus disassembly with Capstone. Details of the supervisor are in supervisor.md.

What C8 is (confirmed)

  • A full-screen image shown by clover-mcp: Errors.Unknown. Decoded, the SNES EUR image reads "C8: An error has occurred". Errors.StartupFailed reads "C1".
  • The images are LZ4 blocks that decompress to a raw 1280x720 BGRA framebuffer.
  • The Lua UI does not show C8. Its own dialogs are C2, C4, C6, C7 and C9 (sys_error_* strings). The string key sys_error_Unexcepted (C8) is not used by any script of the Base.

When it appears

In the NES build, where the handlers are named, the code that draws the failure copies the image path before showing it:

  • executeStartup ("UNABLE TO INITIALIZE SYSTEM") uses Errors.StartupFailed (C1);
  • executeMenuRunning, executeMenuShutdown, executeMenuCommand, executeGameReset, executeGameShutdown and executeTestMenuRunning use Errors.Unknown (C8): a menu or game crash, an unknown menu command, a failure during reset or shutdown.

In the SNES build the same split holds for the handlers that were resolved: start-up and start-menu read the StartupFailed field, start-game and resume-game read the Unknown field. The inlined running/shutdown states of the large execute function were not resolved.

The 20 s timeouts

The SNES and Shonen supervisors wait on an eventfd with a 20 000 000 microsecond select() for the menu to game and game to menu transitions (SNES FUN_0001d710, called from 0x17860 at two places; Shonen FUN_0001dce0). On expiry they record GAME TO MENU TRANSITION TIMEOUT or MENU TO GAME TRANSITION TIMEOUT. The NES supervisor has no such wait.

What is not established

  • That the timeout path ends on the Errors.Unknown image: in the SNES build the splash source of that inlined code was not resolved. By the NES layout it should.
  • What the menu does during the 20 s, and which process writes the eventfd.
  • The game scan (menu.titles.lua) has no time limit of its own; a longer list only matters through the time the menu needs to load it.
  • No allocation-failure path was found that maps to these screens. That is absence of evidence.
